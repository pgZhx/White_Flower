# 规则不确定项 / 冲突

## 1. 6 人局胜利阈值 —— 已确认

✅ **已由用户确认：6 人局使用 `4 / 4`。**

已配置在：

```text
packages/game-engine/src/config/playerCountRules.ts
```

不再视为未确认项。

## 2. 初始金币持有人

Prompt 没有说明第一轮开始时金币由谁持有。

当前实现默认由 0 号座位（第一位玩家）持有。

## 3. 金币能否交给“自己” —— 已确认

金币持有人不能把金币交给自己，只能选择其他仍然拥有未使用水晶的玩家。前端目标列表和引擎校验均应遵守该约束。

## 4. 左右方向定义

Prompt 使用“左侧 / 右侧”，但没有定义相对于座位的方向。

当前实现约定：

- 顺时针 = 右侧（seatIndex + 1）
- 逆时针 = 左侧（seatIndex - 1）

需要确认是否符合实体桌游的座位方向。

## 5. Magic 5 中“仍有手牌”的判定时机

Prompt 写“选择另外两个仍有手牌的玩家 A、B”，但未说明是否包括发动者自己，也未说明如果后续手牌变化如何处理。

当前实现不允许选择发动者自己；目标在魔法生效时必须有手牌；后续行动约束按该时刻玩家是否仍有手牌判断。较早行动玩家决定出牌类型：其出牌后后续玩家必须出牌，其 Pass 后后续玩家只能跟随 Pass。

## 6. Magic 10 的“当前仍至少剩一张手牌”

Magic 10 在所有人行动后、Reveal 前执行。此时“当前仍至少剩一张手牌”指的是执行 Magic 10 时的剩余手牌（不含本轮已出的牌）。

当前实现按该定义处理。

## 7. 终局水晶判定时机

Prompt 说“当所有玩家都已经使用水晶后，当前轮仍然完整执行”，当前实现是在该轮 ROUND_RESOLUTION 后、普通胜负均未触发时执行最终水晶判定。

## 8. 所有玩家 Pass 时 Magic 10 是否仍可发动

Prompt 未明确。当前实现：如果所有玩家都 Pass，则没有“已经出牌的玩家”，Magic 10 无可选目标，自动不发动。
